ABOUT THE PROJECT

See unusual activity sooner.

This system analyzes UPI transaction characteristics and assigns a risk score in real time. It combines anomaly detection with supervised fraud classification to help reviewers prioritize transactions. A score is a signal for review, not proof that fraud occurred.

01 / WHAT IT CHECKS

Behavior, amount, timing

Transaction value relative to a sender's average, time of day, recent activity frequency, new receivers, and location mismatch when both locations are provided.

02 / WHY IT EXISTS

More useful transaction triage

Large unusual amounts, abnormal timing, repeated transfers, and unexpected recipients can be difficult to review manually at scale. Risk scoring helps bring those patterns into one queue.

03 / CRITICAL RISK

Strong configured risk signal

Critical risk indicates that the transaction strongly matches the system's configured high-risk patterns and should be reviewed. It does not mean the transaction is definitely fraud.

HOW IT WORKS

From transaction to review alert

Transaction↓Feature Engineering↓Isolation Forest+XGBoost↓Ensemble Risk Score↓Risk Tier↓Real-Time Alert
ANOMALY DETECTION

Isolation Forest

Estimates how unusual a transaction looks compared with a reference distribution of normal transactions.

SUPERVISED CLASSIFICATION

XGBoost

Uses patterns learned from labeled training data to estimate fraud likelihood for the transaction features.

EXISTING ENSEMBLE

Combined risk score

The backend combines normalized Isolation Forest and raw XGBoost scores using existing weights and applies its configured alert and tier thresholds.

EDUCATIONAL CONTEXT

Why UPI fraud can happen

Potential contributing factors include unusual spending behavior, compromised credentials, social engineering, phishing, and fake payment requests. Amount, time, velocity, recipient novelty, and location differences can be useful review signals. No single indicator proves fraud.
